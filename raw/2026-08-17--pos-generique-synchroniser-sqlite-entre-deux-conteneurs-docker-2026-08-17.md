{"# POS-GÉNÉRIQUE : synchroniser une base SQLite entre deux conteneurs Docker (docker cp   cron)\n\nDate : 2026-08-17 · Portée : générique, tout cas où un collecteur (dans un conteneur) produit une base SQLite qu'un autre conteneur doit servir. Aucun identifiant réel.\n\n## Principe\n\nLe producteur de données et le serveur d'affichage sont deux conteneurs distincts qui ne partagent pas de volume. On synchronise la base par copie via un fichier temporaire sur l'hôte, déclenchée par un cron, plutôt que par un volume partagé (plus lourd à mettre en place).\n\n## Marche à suivre\n\n1. Identifier les deux conteneurs (docker ps) et leurs chemins internes respectifs.\n2. Écrire un script hôte : docker cp producteur:/chemin/base /tmp/base ; docker cp /tmp/base consommateur:/data/base ; docker restart consommateur.\n3. Trouver le conteneur consommateur dynamiquement (grep sur un préfixe stable) car son nom change à chaque redéploiement.\n4. Rendre le script exécutable, l'ajouter au crontab avec une marge après le job producteur.\n\n## Garde-fous\n1. Docker ne supporte pas la copie DIRECTE entre deux conteneurs (docker cp A→B échoue) : passer par /tmp sur l'hôte.\n2. Le chemin interne du producteur n'existe pas sur l'hôte (ex. /opt/data d'un conteneur) : toujours passer par docker cp, jamais par un chemin hôte.\n3. Ajouter la ligne crontab sans passer par crontab -e interactif (source d'erreur) : utiliser `( crontab -l; echo ... ) | crontab -`.\n\n## Difficultés rencontrées\n1. « lstat /opt/data: no such file or directory » : chemin interne au conteneur, pas un chemin hôte.\n2. « copying between containers is not supported » : docker cp direct A→B refusé.\n3. crontab -e qui n'enregistre pas la ligne (éditeur mal quitté).\n\n## Solutions implémentées\n1. docker cp producteur:/chemin → /tmp, puis /tmp → consommateur.\n2. Écrire la ligne crontab par redirection (pipe), pas par éditeur interactif.\n\n## Lessons learned\n1. Un volume partagé est plus propre mais plus lourd ; la synchro quotidienne suffit pour du non-temps-réel.\n2. Toujours tester le script à la main avant de le cronner.\n":""}
